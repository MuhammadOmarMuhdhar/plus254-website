# Design Context

## Users
Developers, data scientists, researchers, and analysts who need programmatic access to Kenyan official statistics (economy, agriculture, governance data). Technically literate, value clarity and speed, need to trust the data source.

## Brand Personality
Trustworthy, precise, Kenyan. Three words: **clean**, **precise**, **authoritative**.

Emotional goals: confidence in data quality and freshness; a public utility done right — approachable but rigorous, like a well-kept lab notebook.

## Aesthetic Direction
Tech editorial with a data-notebook sensibility. Think: *Stripe Docs* meets *engineering graph paper* with *editorial typography* — structured, referenceable, and mathematically grounded.

- **Grid as identity** — 20px graph-paper grid at `rgba(108, 185, 153, 0.15)` on white (`global.css:42-45`, header). Not decoration — the signature. Evokes mathematics, engineering, statistics.
- **Palette** — Green monochrome: `#1f6f54` primary, `#6cb999` card/code surfaces, `rgba(31,111,84,0.15)` muted tint. Warm greys `#1a1a1a`/`#4a4540`/`#6b6560` for text hierarchy. White backgrounds. `--color-ochre: #1e3a5f` defined, reserved (unused).
- **Typography** — Newsreader (serif, headings h1–h3) + DM Sans (sans, body/UI) + `ui-monospace` (code/data). Scale `xs(12px)`→`3xl(clamp 40–64px)` (`tokens.css:6-12`). `tabular-nums` on all numerals/steps; `tracking-wider(0.08em)` on labels.
- **Shape** — `border-radius: 0` everywhere — buttons, cards, code blocks, tables, modals, Pagefind. Sharp corners are the system; precision over softness.
- **Layout** — 960px max content (`BaseLayout`), `65ch` prose. CSS Grid: 3-col action grids / 2-col dataset/blog/api cards → 1-col at 768px. 185px sticky sidebar + flex main on inner pages (About, Datasets, API Docs, blog analysis) → horizontal scroll at 900px → `<details>` dropdown at 480px. Fluid spacing `clamp()` scale.
- **Animation** — CSS only. Card lift `translateY(-3px)` + `shadow-md`, button `scale(1.03)`, arrow `translateX(4px)`, `ease-out-quart` (`cubic-bezier(0.25,1,0.5,1)`). Cursor blink on API URL. No entrance/scroll animations. `prefers-reduced-motion` kills all (`global.css:92-101`).
- **Theme** — Light only. Print strips grid/drawers.

## Design Principles
1. **Grid is the system** — the graph-paper is not background, it is the organizing logic. Align to it.
2. **Trust through restraint** — every element earns its place; no decorative noise.
3. **Hierarchy through type** — size, weight, and tracking create structure, not boxes and borders.
4. **Data is the interface** — tables, schemas, statistics, and code are primary content. Present them with the same care as prose.
5. **Performance is polish** — fast loads, no layout shift, 60fps transitions. Pure CSS.
6. **Accessibility is non-negotiable** — WCAG AA contrast, `focus-visible` green outline (`global.css:87-90`), keyboard nav, `prefers-reduced-motion` respected.

## Layout System
- **Shell** — `BaseLayout.astro` (Header + main 960px + Footer + Pagefind modal, `theme-color #1f6f54`).
- **Inner pages** — `AboutLayout` / `DatasetsLayout` / `APIDocsLayout` share 185px sticky sidebar pattern with IntersectionObserver scroll-spy and left-border active indicator.
- **Homepage** — `Hero.astro` (serif headline, 2 CTAs) + `FeaturedData.astro` (narrative + Datawrapper embed) + `ActionGrids.astro` (2× 3-card grids).
- **Datasets** — Index groups by topic (Economy/Agriculture/Network/Governance) in 2-col card grids; detail pages show breadcrumb, meta (source/endpoint/rows), `dataset-table` with `data-label` mobile stacking, summary statistics.
- **Blog** — Index 2-col post cards; post layout switches on `toc` frontmatter: tutorial (`65ch` centered) vs analysis (185px TOC sidebar + wide main).
- **API Docs** — Method badges, param tables, language tabs (curl/Python/JS from `samples[]` array), response blocks, URL with blinking cursor, pagination patterns.
- **404** — Centered with large `color-green-muted` watermark number.

## Content Editing
All user-facing copy is hoisted into a single `content` const at the top of each page/component's frontmatter — markup below only references it. Follow this pattern for any new page.

- **Data at the top, markup below.** Never hardcode copy mid-markup; hoist into typed consts/arrays (see `Hero.astro`, `ActionGrids.astro`).
- **Collections for bulk content.** Datasets and blog posts live in `src/content/` markdown with schemas in `src/content.config.ts`. Marketing-page copy stays in code.
- **Prose → string arrays.** Map over arrays for paragraphs/tables/steps; `set:html` only for strings with inline `<code>` or `<a>` (author-controlled).
- **Code samples → data.** Language tabs render from `samples: {lang, code}[]` — adding a language is one entry.
- **Shared values → modules.** `topicNames`/`topicOrder` live in `src/lib/datasets.ts`.
- **Never hardcode numbers that drift.** Compute counts from the content collection (e.g. dataset counts).
